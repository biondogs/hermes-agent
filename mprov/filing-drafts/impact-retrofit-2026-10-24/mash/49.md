Fixes #18

A `.mash` script template like `{{ ''.__class__.__mro__[1].__subclasses__()|length }}` renders `513`: it walks dunder attributes out of Jinja into live Python objects, with the invoking user's permissions (`__mro__` → subclasses → `__globals__` → arbitrary code execution). `renderString` in `src/mash/app.py` built a plain `jinja2.Environment`, which permits attribute traversal into interpreter internals.

## The fix
Build `jinja2.sandbox.SandboxedEnvironment` instead (import + constructor only, 3+/2-). Denied attribute access raises `SecurityError`, which the existing handler catches, so a blocked template degrades to the raw string as before.

## Impact

Touches script template rendering. Before: dunder payloads in a script execute arbitrary Python with the user's permissions; after: `SandboxedEnvironment` denies the walk and the template degrades to the raw string. Files: `src/mash/app.py`, `tests/test_render_sandbox.py`.

## Testing
New `tests/test_render_sandbox.py`: `__mro__` and `__globals__` payloads are RED on base (`36ef120`: renders `513` / leaks `__builtins__`) and GREEN on fix; plain interpolation unchanged; full suite 36/36.
