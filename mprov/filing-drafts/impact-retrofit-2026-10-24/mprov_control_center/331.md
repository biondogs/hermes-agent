The shared PATCH implementation replaces an anonymous request user with a hard-coded admin superuser before performing the update (`common/views.py:170-173`, at `6afb414`). Because the class's permission gate accepts an API key without authentication (#315), any key-holding caller executes writes as the superuser: audit fields record admin, and no per-user write check can distinguish the real actor.

**Fix:** reject anonymous mutations instead of impersonating a superuser; require an authenticated session for PATCH, and derive any system-account behavior from an explicitly named, limited service account rather than a hard-coded one.
