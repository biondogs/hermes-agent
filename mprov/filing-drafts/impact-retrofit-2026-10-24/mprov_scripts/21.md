Image builds on a host whose node fstab lacks a trailing newline produce a corrupt fstab — the NFS entry concatenates onto the last line and boot drops to emergency mode — while a fstab merely mentioning /export/data in a comment or stale entry silently skips the needed mount so /data never mounts.

`image-gen/setup_data_share_mount.sh:23` uses `grep -qF '/export/data' /etc/fstab || echo "…" >> /etc/fstab`: a substring match for idempotence plus append without ensuring the previous line ends with a newline. Both failure modes verified by execution with the script's exact logic at commit eb80617; the line was introduced by upstream fix 56e1991.

**Fix:** match the intended mount entry at field level (the /data mount point) and guarantee a newline before appending.

Impact: touches the NFS /data fstab entry added during image builds; prod today a missing trailing
newline or a comment mentioning /export/data corrupts or skips the entry, expected:
field-level match and newline-guarded append. Files: `image-gen/setup_data_share_mount.sh`.

Severity: S3 — happy path works; two named adverse fstab shapes yield severe or silent failure.
