Any script-runner helper script subclassing MProvScript and using `self.ip_address` gets tuple data — `(('127.0.0.1', 49942))` — instead of the address string; posted/consumed values are garbage.

`src/mprov_jobserver/script.py:80-83` assigns the tuple directly (`address = s.getsockname(); self.ip_address = address`) — a copy-paste slip missing the `[0]` subscript that `app.py:371-374` gets right with sockinfo[0].

**Fix:** `self.ip_address = address[0]`, and close the fromfd duplicate socket.

Impact: touches the MProvScript helper API for script authors; prod today `self.ip_address` holds an (address, port) tuple so scripts post garbage values, expected: the address string. Files: `src/mprov_jobserver/script.py`.

Severity: S3 — broken template API for the documented extension point.
