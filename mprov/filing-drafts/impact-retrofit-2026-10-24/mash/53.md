Fixes #26

In a piped script, a failed API call (e.g. HTTP 500 from `delete`) left `MPROV_RESULT` holding the previous command's result; a following `pvar MPROV_RESULT` showed stale data. `_sendHttpRequest` in `src/mash/app.py` returned early on five error paths — communications error, unknown model, model without registered endpoint, no argument, unsupported method — without clearing it; only the two argument-validation branches and the success-path JSON-exception handler did.

## The fix
All error returns funnel through one `_httpErrorExit()` helper that sets `MPROV_RESULT = None`, so new error branches cannot forget it. Success and background behavior is unchanged.

## Impact

Touches the request dispatcher's error exits. Before: a failed call left `MPROV_RESULT` holding the previous command's data; after: every error path clears it. Files: `src/mash/app.py`, `tests/test_stale_result.py`.
