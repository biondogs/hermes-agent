Fixes #170

Every image build ran `wget` to the fixed world-writable path `/tmp/busybox`, ignored its exit code, then `chmod 0755`'d and executed whatever file sat at that path — as root. `image_update.py` assumed a fixed `/tmp` path and a successful download: no wget exit-code check, no verification of the fetched bytes before exec, so a failed download or a binary planted by any local user would run as root.

## Change
- `image_update.py` downloads to `imageDir/.busybox` (created mode 0700), fails the job when wget returns nonzero, and verifies the file's ELF magic before `chmod`/exec; the pack step execs the binary from that verified path.

## Impact
Touches image-build busybox fetch. Before: unchecked wget to `/tmp/busybox`, whatever lands there runs as root. After: verified fetch to a root-only dir. Files: `src/mprov_jobserver/plugins/image_update.py`, `tests/test_image_update.py`.

## Testing
Three regression tests (root-only fetch path and dir mode; failed download fails the build; planted non-ELF binary never executed): RED on base `df027c6`, GREEN on head `eccbb28`. `tests/test_image_update.py`: 24 passed, 5 xfailed, no other suite deltas.
