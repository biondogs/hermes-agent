**Symptom.** `script_runner.handle_jobs()` touched `/etc/nologin` before any argument or entity validation, and only removed it on the success path. A bad invocation (`-h`, `-i` with `-s`, no `-i`/`-s`) or a failed entity load left the file behind, locking users out of the node.

**Root cause.** Creation happened at the top of the function; every early `return False` / `exit(1)` and any exception in the script region skipped the single `unlink` at the end.

**Fix.** Move the touch until after all validation, just before the scripts run, and wrap the script region in `try/finally` so the file is lifted on every exit path.

## Impact
Touches script-runner startup. Before: bad invocations left `/etc/nologin` behind, locking logins. After: the touch happens only after validation and is lifted on every exit path. Files: `src/mprov_jobserver/plugins/script_runner.py`, `tests/test_script_runner.py`.

**Test evidence.** `tests/test_script_runner.py`: bad-argument and entity-load cases assert `/etc/nologin` is never created; an error inside the script region asserts it is still removed. 5 regression cases RED on base `df027c6`, GREEN on `957d5d0` (16 passed, 3 xfailed; no other outcomes changed).
