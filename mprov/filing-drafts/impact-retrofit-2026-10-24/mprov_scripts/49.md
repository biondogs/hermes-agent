Fixes #28

On current main (`a44f519`) the role and playbook loops in `image-gen/run_ansible.sh` never run, and the collections loop installs wrong-run-mode entries — reproduced in the Rocky 9 test image. The filed mechanism needs correction: bash's double parse of backticks collapses the over-escaped quotes into a valid program, so there is no jq compile error on the target stack, and reducing the escapes alone is a verified no-op. The loops die because optional entity keys (`osdistro`, per-group `ansibleroles`) project nulls into the flattened array; `select(.[].scriptType.slug|startswith(...))` aborts on a null before emitting matches and re-emits whole arrays.

## The fix
Pass the run mode with `--arg` and select per-element null-safely (`map(select(.scriptType.slug // "" | startswith($m)))`). Only the three jq programs change.

## Impact
Touches the image-build ansible loops. Before: the loops emit nothing, so
configured ansible content never installs. After: each loop iterates its matching
entries. Files: `image-gen/run_ansible.sh`, `tests/test_run_ansible.py`.

## Testing
`tests/test_run_ansible.py` stubs the ansible commands and asserts each loop fires exactly for matching entries: 2 failed on base, 22 passed on fix.
