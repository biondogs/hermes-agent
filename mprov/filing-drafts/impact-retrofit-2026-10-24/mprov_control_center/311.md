PXE provisioning from admin and API power-cycles a node even when setting its boot device failed — wrong BMC password, unreachable BMC — and the flow reports success while the node reboots into its old OS.

`systems/views.py:917-920` and `systems/admin.py:289-292` run the ipmitool command through `subprocess.run` with the result discarded and only `OSError` caught: application-level failures are indistinguishable from success, no timeout is set, and the forced chassis reset proceeds regardless.

**Fix:** check the return code, add a timeout, surface stderr to the response/admin message, and skip the forced reset when bootdev failed.

Impact: touches PXE one-shot provisioning on power-cycle; prod today a failed ipmitool bootdev is ignored and the flow reports success into the old OS, expected: bootdev checked and failure surfaced. Files: `systems/views.py`, `systems/admin.py`.

Severity: S3 — happy path works; adverse BMC condition yields a false success found only by hand.
