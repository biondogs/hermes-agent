Fixes #174

Post-boot/image script failures were silent: `script-runner` printed "complete." and the runonce process exited 0 even when scripts failed. `runScript()` ignored the subprocess return code, a thread that died before its subprocess started (e.g. a download failure) was swallowed at join, and `handle_jobs()` never inspected anything before reporting completion.

## Change
- Each script thread records its return code — or an error string when it never started — into a shared dict. After joining every step, `handle_jobs()` reports failure to the mPCC if any script returned nonzero; in runonce mode `JobServer.start()` exits 1 when a jobmodule's run failed.

## Impact
Touches script-runner result reporting. Before: failed post-boot and image scripts exited 0 and reported success. After: nonzero return codes and never-started scripts flip the job to failed, and runonce exits 1. Files: `src/mprov_jobserver/app.py`, `src/mprov_jobserver/plugins/plugin.py`, `src/mprov_jobserver/plugins/script_runner.py`, `tests/test_app.py`, `tests/test_script_runner.py`.
