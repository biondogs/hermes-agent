Fixes #177

`repack_image` could destroy the image it repacks: a run against an image directory exited 0 and left an empty, invalid `.img`. The script deleted the existing image before tarring; the tar invocation was broken (`-C $1-f`: missing space, no operand, unquoted paths); and the `tar | gzip` pipeline masked tar's exit status, so garbage got `mv`'d over the image.

## Change
- `set -euo pipefail`, quoted path arguments, correct `-C "$dir" -f -` invocation. The new image is built beside the old one and swapped in with a same-filesystem `mv` only after tar and gzip succeed; the existing image is parked outside the tarred tree (busybox tar lacks `--exclude`) and restored on failure.

## Impact
Touches the `repack_image` helper. Before: one run destroyed the image (delete before a broken tar). After: the new image is built beside the old and swapped in after tar and gzip succeed. Files: `repack_image`, `tests/Dockerfile`, `tests/test_repack_image.py`.

## Testing
`tests/test_repack_image.py` (new): RED on main (`ReadError: empty file`; rc 0 with the image destroyed), GREEN on the fix; verified end-to-end against real busybox 1.36.1.
