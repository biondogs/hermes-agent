An image name containing path components makes image-grab mirror the node OUTSIDE the image store, and with -d, `rsync --delete` removes there whatever files the node lacks — e.g. `image-grab.sh -n node01 -i ../../etc -d` overwrites/deletes two levels above the store.

`tools/image-grab.sh:53-56` runs `mkdir -p "$IMAGE_DIR/$IMAGE_NAME/"` on the raw name, and `:68` syncs `rsync … $DELETE root@$NODE:/ $IMAGE_DIR/$IMAGE_NAME/`.

**Fix:** validate IMAGE_NAME against a strict identifier pattern (no separators) and assert the resolved destination stays inside IMAGE_DIR before creating or syncing anything.
