**Symptom.** Saving a NetworkInterface row silently replaced a user-set per-interface `hostname` with the parent System's hostname (issue #322).

**Root cause.** `NetworkInterface.save()` in `systems/models.py` unconditionally assigned `self.hostname = self.system.hostname` on every save.

**Fix.** Default `hostname` from the parent System only when the row carries no hostname. Create-time defaulting (field left blank) is unchanged; a hostname an operator sets now survives every later save.

**Tests.** New `systems/test_network_interface_hostname.py` covers create-time defaulting, user-set hostname surviving re-save, and blank hostname re-defaulting. The user-set-hostname test fails on base `781ac6f` (`AssertionError: 'node-01' != 'eth1-label'`) and passes with the fix. Full suite: 166 tests OK.

## Impact
Touches NetworkInterface saves in the systems app. Before: every save overwrote a user-set per-interface `hostname` with the parent System's. After: the System hostname defaults the field only when blank, user-set values survive re-saves. Files: `systems/models.py`, `systems/test_network_interface_hostname.py`.
