Fixes #316

`GET /systembmcs/?detail` returned every BMC row with its `password` in cleartext — one authenticated GET harvested every BMC credential (reproduced on main @ `781ac6f`). `SystemBMCDetailSerializer` serves `fields='__all__'`; ed147bf made the password write-only on the list serializer but deliberately left the detail path, because mprov_scripts' `setupBMC.py` reads its password from `?system=<id>&detail`.

## The fix
The password is now served only when the request is scoped to one system: `/systembmcs/<pk>/` or `?system=ID&detail` — setupBMC.py's exact query. Unscoped `?detail` uses a new `SystemBMCDetailNoPasswordSerializer` with the password write-only. Jobserver `dns.py`'s `?network=…&detail` read never touches the password, and setupBMC.py needs no change.

## Impact
Touches `/systembmcs/?detail` in the BMC API. Before: one unscoped `?detail` GET returned every BMC password. After: passwords served only for one system (`?system=ID&detail`), setupBMC.py unchanged. Files: `systems/serializers.py`, `systems/views.py`, `systems/test_detail_serializer.py`, `systems/tests.py`.
